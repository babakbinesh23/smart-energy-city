## Practical triage workflow

1. New feature/bug request: reproduce and classify under existing Issues; describe affected device/browser.
2. Security/private-data reports: use private GitHub security reporting, not public issue details.
3. Changes: small reviewed PR, tests, build, clear scope, and updated educational assumptions.
4. Releases: use version tags and documentation tied to tested commits, no false backdating.
5. Monthly maintenance: review open issues, document what changed, identify real community feedback, and mark blockers.
